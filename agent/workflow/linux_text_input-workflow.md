# Typing punctuation from Linux keyboard shortcuts

Researched 2026-10-25 for Debian KDE.

* Determine X11 versus Wayland before recommending an injection tool. The agent process environment reported `XDG_SESSION_TYPE=wayland`; this does not prove the session on another target machine.
* On X11, `xdotool type --clearmodifiers -- '—'` temporarily clears active modifiers and restores them afterward. `xdotool key --clearmodifiers emdash` is another option using an X keysym. No clipboard change is required. Source: https://manpages.debian.org/trixie/xdotool/xdotool.1.en.html
* xdotool is not a general solution for native Wayland apps. Upstream documents the limitation: https://github.com/jordansissel/xdotool#wayland
* Do not assume that ydotool key-up events release modifiers held on a separate physical keyboard. Its modifier-clearing request is tracked at https://github.com/ReimuNotMoe/ydotool/issues/81 . A fixed sleep only gives the user time to release keys; it cannot guarantee release.
* KWtype targets KDE Wayland, but its inspected source does not clear held physical modifiers; unmapped Unicode falls back to Ctrl+Shift+U, which is not universally supported by applications. Do not present it as a universal punctuation insertion solution. Sources: https://github.com/Sporif/KWtype and https://raw.githubusercontent.com/Sporif/KWtype/master/src/main.cpp
* No typing injection was tested in the user's desktop during this research.
* The user confirmed that the target is this environment. Read-only host inspection found Plasma 6.3.6, dotool 1.6 at `/usr/local/bin/dotool`, qdbus6, Python 3, membership in `input`, and `/dev/uinput` plus `/dev/input/event*` accessible to that group. Sandbox views hide input devices and supplementary groups; do not infer missing host permissions from the sandbox view.
* `../../monochrome/bin/clip` is a Bash wrapper around `qdbus6 org.kde.klipper /klipper setClipboardContents "$@"`; no wl-copy installation is necessary here.
* Prepared `context/projects/type_punctuation/type_punctuation-insert.sh`, a Bash script with a Python standard-library helper. It polls EVIOCGKEY(32) on input devices until keycodes 0..255 are released for 50 ms, with a 15 s timeout; then sets the clipboard through Klipper and invokes dotool for Ctrl+V (or Ctrl+Shift+V with `--terminal`). It replaces clipboard contents and requires the existing input-device access. The lock drops overlapping invocations. A later new keypress can still affect injection; dotool has device-registration latency. Sticky/latched desktop modifiers are not measured by physical key-state polling. Bash syntax was checked; no live paste was attempted.
* EVIOCGKEY queries are documented by the Linux kernel: https://www.kernel.org/doc/html/latest/input/event-codes.html and https://github.com/torvalds/linux/blob/master/include/uapi/linux/input.h . Installed dotool's help confirms its stdin `key CHORD` interface; upstream manual: https://github.com/nick-tgcs/dotool/blob/develop/doc/dotool.1.scd .
* For hotkey latency, prefer an existing `dotoold` via `dotoolc` over a fresh `dotool` process. On this host, single no-input startup measurements were 872.39 ms for dotool versus 8.02 ms for dotoolc. A running daemon and its `/tmp/dotool-pipe` were present. Reusing the daemon is documented upstream under LONG-RUNNING INSTANCE. Do not present these component timings as end-to-end shortcut latency. Task state, revert details, candidate, and JSON measurements are in the `context/projects/type_punctuation/` files.
* When the requirement is character insertion while Alt remains physically held, prefer investigating a native XKB character mapping rather than waiting for release in an injected paste script. XKB types can consume modifiers used for symbol selection; see https://xkbcommon.org/doc/current/group__state.html . This requires disabling any competing global shortcut for that chord. No native Alt mapping has been tested in this task. KWin 6.3.6 fake-input protocol is not a simple way to release physical modifiers: its backend ignores releases of keys absent from its own device's pressed-key set (https://raw.githubusercontent.com/KDE/kwin/v6.3.6/src/backends/fakeinput/fakeinputbackend.cpp).
* KWin 6.3.6 supports live keyboard reload via a D-Bus signal: path `/Layouts`, interface `org.kde.keyboard`, member `reloadConfig` (https://github.com/KDE/kwin/blob/v6.3.6/src/keyboard_layout.cpp). A newly created user XKB directory may still require a new session because the existing XKB context registered only directories present at initialization. Do not imply every mapping edit needs logout, or guarantee live loading from a newly created directory. KWin also requires `ResetOldOptions=true` to read its `Options` entry (https://github.com/KDE/kwin/blob/v6.3.6/src/xkb.cpp).
* An isolated ctypes context in the installed libxkbcommon can validate custom rules, symbol selection, and consumed modifiers without changing the active layout or installing xkbcli. The task's example validator and JSON results are `context/projects/type_punctuation/type_punctuation-xkb_validate.py` and `context/projects/type_punctuation/type_punctuation-xkb_validation.json`. Library-level checks do not establish behavior in every application.
