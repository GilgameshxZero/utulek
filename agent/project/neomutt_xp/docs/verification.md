# Verification history and coverage

Validation uses synthetic inputs, disposable homes/mailboxes and isolated
fixture servers. Test harness sources are in `tests/`; no production account or
credential is used, and configured settings are reproduced with fake data.

## Native application

The current UI candidate passed actual Windows system/editor ConPTY navigation,
reading, search, Unicode subject serialization, editor handoff, discard, flags,
purge, tagged moves, postponement, restart/recall and clean exit using synthetic
mail. Parsed terminal screens validate resize and editor-return layouts on both
Windows terminal implementations; Linux screen checks also pass. Native Windows
HTML/Lynx, calendar mailcap display and synthetic contact queries pass.
IMAP regression fixtures use rootless Dovecot servers and verify server state
after UI operations, concurrent per-flag edits, connection loss, pending
deletion, sequence-number changes and UIDVALIDITY replacement on Linux and both
Windows terminal implementations. Reconnect recovery retains pending flag deltas
in memory; this is not durable offline editing across process crashes.

Native calendar macros exercise invitation responses, request generation and
owned-attachment cleanup. Calendar replies retain the request's revision and
recurring-instance identity and serialize their timestamps as UTC. The shared
configuration patch in `patches/calendar-mime_parameters.patch` gives reply and
request attachments their corresponding MIME method parameters. Protocol checks
and serialized UI drafts cover these properties on Linux and both Windows
terminal implementations; this alone does not establish Google Calendar
interoperability. The cancellation regression covers acknowledging an external
helper failure; Windows uses console events for that single-key prompt and
flushes pending input without a blocking CRT drain read.

Native file/process/cache regression sources and terminal harnesses are in
`tests/`. Actual SMTP/TLS fixture tests cover password/OAuth authentication,
encrypted fixture passwords/tokens, trust rejection and interrupted submissions
on both platforms. Native sendmail process execution passes capture-only
success/failure/background checks on both platforms. The configuration parser
also consumes real GPG-encrypted synthetic settings. Interactive Windows GPG
loopback pinentry passes through both ConPTY implementations: a typed passphrase
stays hidden and decryption succeeds. PGP/MIME reader tests pass on Linux and
both Windows terminal implementations; the correct passphrase decrypts the
synthetic message into the pager, and wrong or cancelled input reveals no
plaintext. Native anonymous temporary files use exclusive creation, private
ACLs and deletion sharing, preserving NeoMutt's open-then-unlink behavior.

## Windows terminals and text

Windows reverse-video cells preserve terminal default colors rather than
swapping fixed palette entries. Default-colored bold text keeps the theme's
foreground color; the legacy console cell API cannot represent a separate bold
font weight for that default color. Explicit palette colors retain intensity.

Windows prompt storage and decoded-header filtering preserve supplementary
Unicode characters independently of the system's 16-bit `wchar_t`. Console input
accepts both ordinary Unicode key events and Alt-release Unicode generated by
system ConPTY. Regression checks verify typed, edited, CLI-prefilled and long
subjects, deletion of a supplementary character, and postponement/restart/recall
using both Windows ConPTY implementations. The native curses rendering ABI still
limits glyph display: supplementary characters use escapes in prompts, and some
other views can show replacement glyphs. Stored and serialized subject text is
preserved.

## Attachments and HTML

The attachment tests cover production mailcap invocation, base64/Unicode HTML,
spaced paths, actual isolated Edge/Chromium rendering, failure status, and
overlapping cleanup timers. HTML keeps its existing stable filename and
64-second lifetime; reloading a browser tab after cleanup still requires
reopening the attachment.

## Calendar

Calendar workflow fixtures mirror the shared configuration with fake
credentials and isolated mailboxes/calendar storage, and exercise both reply
bindings, response choices, save, display and discard cleanup. Reply-address
drafts are compared against stock Linux behavior, including self-replies and
Reply-To. These checks do not certify every mailbox failure or synchronization
race. The calendar helper's direct-send path emits a primary calendar REPLY.
Stock-compatible attachment reply macros use the shared Python helper, private
staging and standard compose operations; no calendar-specific NeoMutt command
is included.

## Submission reliability

The shared SMTP implementation distinguishes a lost final DATA acknowledgment
from a definite rejection. If the terminator may have reached the server but no
valid response arrives, it reports that delivery status is unknown and the
server may have accepted the message. It retains the draft and does not
automatically resend. A received acceptance remains successful if the connection
closes during QUIT. Recording follows acknowledged submission.

`tests/check_smtp.py` covers isolated authentication/TLS and archive consistency,
including Unicode calendar/image attachments. The Windows and Linux SMTP outcome
UI checks exercise compose/send, retained draft content, no automatic resend and
archive counts. Classic GPG reader, sign and encrypt checks use a disposable
keyring and genuinely encrypted messages (GPGME remains available but is not the
Windows default).

Maildir rescans retain subsecond timestamps on both platforms and detect
timestamp changes in either direction. Concurrent flag changes are merged
against the last observed filename: local changes to individual flags take
precedence, while external changes to other flags and custom flags are retained.
A failed deletion or a source disappearing during synchronization reports
failure and retains the pending changes, allowing a retry. Maildir operations
are not a transaction across multiple files; arbitrary filesystem races remain
possible.

## Windows tmux

The pinned native tmux-win 3.6a-win32.7 release disables console line wrapping
while advertising automatic margins. Its output can leave old NeoMutt rows and
colors on screen. `../tmux_win/patches/console_wrap.patch` restores the required
Windows output mode. `../tmux_win/scripts/build_windows.ps1` rebuilds it with
existing MSVC and static libevent from hash-pinned development inputs in
`.obj/`. `tests/check_windows_tmux.js` checks actual scroll, pager,
detach/reattach and resize interactions with explicit and default/reverse colors
on both ConPTY implementations. It uses isolated tmux servers and synthetic
mail.

## Live Google Calendar

The installed single-file Windows build produced tentative, declined and
accepted states from disposable events on 2026-11-11. Google processes email
RSVPs asynchronously; a submitted reply can take minutes (occasionally much
longer) to change the organizer-visible state. Poll for the calendar
notification or the guest summary rather than treating a short delay as failure.
